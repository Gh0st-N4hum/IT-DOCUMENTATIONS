
# LAN Connected but No Internet (DNS Timeouts)

**Date:** 2026-10-07
**Category:** Network
**Status:** Resolved

---

## Problem Summary

A Windows 10 PC on a wired LAN could reach the internal server and authenticate with `net use`, but had no internet access in any browser. The PC held a valid private IP address, so this was not the usual 169.254.x.x DHCP failure.

---

## Symptoms

* Internal server reachable, `net use` login worked
* Browsers (Chrome and Edge) could not load any website
* Tray network icon showed no internet connectivity
* `ping 8.8.8.8` and a ping to the router succeeded
* `ping google.com` failed and `nslookup google.com` timed out

**Error Message (if applicable):**

`Ping request could not find host google.com. Please check the name and try again.`

`DNS request timed out. timeout was 2 seconds.`

---

## Investigation

Document the troubleshooting process and what you discovered.

### Step 1 — Tested connectivity layer by layer

Pinged the router (`172.16.0.1`), then `8.8.8.8`, then `google.com`.

**Result:** The router and 8.8.8.8 replied with 0% loss. The `google.com` ping failed with "could not find host". Routing worked, name resolution did not.

### Step 2 — Tested web traffic and proxy settings

Ran `curl -I http://1.1.1.1` and `netsh winhttp show proxy`.

**Result:** curl returned an HTTP 301 from Cloudflare, so web traffic passed without DNS. WinHTTP reported direct access (no system proxy). Browsers keep their own proxy setting, so this did not fully rule out a browser proxy.

### Step 3 — Tested DNS and reviewed adapter settings

Ran `nslookup google.com` and opened the IPv4 properties in `ncpa.cpl`.

**Result:** Every DNS query to 8.8.8.8 timed out. The adapter had a static IP, a wrong default gateway (`172.16.1.0` instead of `172.16.0.1`), and manually entered DNS servers (8.8.8.8 and 1.1.1.1). Also noted that the first IP reported (`172.168.1.22`) was outside the private 172.16.0.0 to 172.31.255.255 range.

### Step 4 — Corrected the gateway and switched to DHCP

Set the gateway to `172.16.0.1`, switched the adapter to automatic IP, ran `ipconfig /flushdns`, then `ipconfig /release` and `ipconfig /renew`.

**Result:** The release dropped the working lease and the renew failed, leaving the PC with only an IPv6 link local address and no IPv4 address. Errors seen: "The operation failed as no adapter is in the state permissible for this operation", "An address has not yet been associated with the network endpoint", and "The name specified in the network control block (NCB) is in use on a remote adapter."

### Step 5 — Checked the DHCP Client service

Ran `net start dhcp`.

**Result:** "The requested service has already been started." The service was not the cause.

### Step 6 — Disabled IPv6 on the adapter

Opened `ncpa.cpl`, Ethernet, Properties, and unchecked Internet Protocol Version 6 (TCP/IPv6).

**Result:** The PC regained a working network configuration and internet access.

---

## Root Cause

> **Root cause:** Undetermined
> **Most likely cause:** The IPv6 binding or a stuck adapter state was interfering with DHCP and DNS on this adapter. Disabling IPv6 resolved it, but the exact mechanism was not confirmed. Contributing misconfigurations were also found: a wrong static gateway (`172.16.1.0`) and stale manual DNS entries, which Windows keeps even after the IP is set to automatic.

---

## Resolution

1. Corrected the default gateway to `172.16.0.1`
2. Reviewed IP and DNS settings, switching the adapter to obtain both automatically
3. Unchecked Internet Protocol Version 6 (TCP/IPv6) in the Ethernet adapter properties

## Lessons Learned

A valid IP only proves the local subnet works. Internet access also needs a correct gateway and working DNS, so test in layers: gateway ping, then a raw IP ping (`8.8.8.8`), then a name ping. If the IP ping works and the name ping fails, the fault is DNS, not routing.

Manual DNS entries stay in place when the IP is switched to automatic, so always check both sections of the IPv4 properties. Check the address range too: `172.168.x.x` is public space, while the private range is `172.16.x.x` to `172.31.x.x`.

Avoid `ipconfig /release` on a working connection unless you can recover, because a failed `/renew` leaves the PC with no IPv4 address. Disabling and enabling the adapter forces a fresh DHCP request more safely. If the network stack seems corrupted, `netsh winsock reset` and `netsh int ip reset` (as Administrator, then restart) are the next options.
